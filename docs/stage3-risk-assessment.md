# Risk assessment — WebRTC echo-test change, before live deployment

No numerical failure probabilities below — none would be grounded in real
data. Each row is evidence, prevention, what's still genuinely uncertain,
and the condition that means stop/roll back immediately.

| Risk | Evidence so far | Prevention built in | Remaining uncertainty | Stop/rollback condition |
|---|---|---|---|---|
| **Existing-call disruption** (101/102/Telnyx) | Reload-not-restart confirmed on a version-matched local instance, both directions (enable and disable), with process uptime unchanged. `transport-udp` has `allow_reload=no` (Asterisk's own default), which blocks any accidental edit to it from taking effect without a restart — so even a mistake in editing it wouldn't silently apply. The change only *adds* new objects. | Backup of all three files before touching anything; reload commands only, no restart; change is additive-only, never edits 101/102/telnyx-* sections. | Local Asterisk and the live one are the same package version, but not the same uptime/history/memory state. A reload has not been tested on *this specific* long-running process, under live trunk registration. | Any drop in `pjsip show contacts` for 101, or `pjsip show registrations` for telnyx-aor, immediately after reload → roll back immediately. |
| **Memory/CPU exhaustion** | Live server has ~654MB RAM available of 952MB total (confirmed, this session). The new objects are config-only until a call actually happens; the echo test's own resource cost was not separately profiled (the Docker test's resource use isn't representative of the bare-metal VM). | Change is config-only until exercised; nothing new runs continuously; no new persistent service added to this host by this specific change (the gateway, if later deployed here, is a separate decision). | Real RSS cost of one active WebRTC/ICE/DTLS-SRTP call under PJSIP has not been measured on this VM. On a ~1GB box this matters and hasn't been load-tested. | If `free -h` available memory drops sharply or swap usage climbs during/after testing → stop, investigate before any further calls. |
| **One-way audio** | Not yet observable either way — the local test never reached a connected ICE state at all (NAT artifact of the Docker test topology, explained in the change package), so "one-way" vs "no way" vs "two-way" hasn't been distinguished yet. | `webrtc=yes` sets DTLS-SRTP, rtcp_mux, ICE support, matching Asterisk's documented WebRTC defaults — a necessary but not sufficient condition. | Real NAT/ICE behavior on the live server's actual public IP, with a real client, is unverified. This is the single biggest open question before calling this "working." | Any one-directional audio report during actual testing → do not proceed to a real pilot; treat as blocking, not cosmetic. |
| **Missed incoming calls** (101/102) | This change adds a transport and one *new*, isolated endpoint (`webrtc-test`). It does not touch the dialplan contexts, AORs, or endpoints that 101/102/Telnyx inbound routing depends on (`from-telnyx`, `inbound-main`, `inbound-outreach` are untouched — confirmed by reading `extensions.conf`'s section list). | Dialplan reload is scoped to extensions only, and the new context (`webrtc-test`) doesn't intersect with `inbound-main`/`inbound-outreach`. | None identified specific to this change — the two codepaths are structurally separate. | Any change in 101/102's answer rate immediately following this deployment → investigate before attributing it to anything else, but there's no structural reason for this change to cause it. |
| **Unauthorized access** | New listener is bound to `127.0.0.1` only (verified: `bindaddr=127.0.0.1`, already the case on the live file). No firewall/NSG rule change proposed or made. The test endpoint's password is a fresh random value, not reused from local testing, never committed to git. | Loopback-only bind; SSH tunnel is the only path in; `/admin`-style static-token patterns are explicitly flagged elsewhere as a stopgap to replace before any real exposure. | This is only safe as long as nothing *else* later opens 8088 to a wider bind address without equivalent scrutiny — worth flagging for whoever does that later, not just now. | Any sign the port is reachable from somewhere other than localhost/the SSH tunnel → treat as a live incident, not a config question. |
| **Unexpected charges** | Echo extension is 100% internal — no Telnyx leg, confirmed by the dialplan (`Answer()` → `Echo()` → `Hangup()`, never touches `outbound-main`/`outbound-outreach`). STUN server used in local testing was Google's free public one; nothing paid was activated anywhere. | No external call path in the new dialplan context at all. | None identified — there is no code path in this change that can reach Telnyx. | N/A for this specific change; stays relevant once real PSTN testing starts, which is explicitly a separate, later, flagged step. |
